## 2. 보고서가 놓친 정확성 문제 (판정에 영향)

| 글 | 글의 created_at | 보고서가 OK 로 본 "이전 모델" | 그 모델의 created_at | 실제 선후 |

원인: 발행 글 전부가 같은 날(2026-09-05) 발행돼 `find_previous_model` 의 1차 키(published_at)가 동률이고, 2차 키가 created_at **내림차순**이라 가장 새로 등록된 형제 모델이 뽑힌다. 그 결과 글은 "이전 모델 Qwen-Drive-1.0-4B 대비 파라미터 517.8% 증가"라고 쓰지만, HF 상으로는 Qwen3.8-27B 가 먼저 나온 모델이다. 수치 계산은 맞아도 '이전'이라는 서술이 HF 사실과 어긋나므로 Goal 의 "HF API 에 없는 사실을 지어내지 않는다"에 걸린다. 보고서 4절은 task 일치만 보고 선후 관계를 검증하지 않았다.

## 3. 그 외 개선점

- 보고서 11절 '하' 지적(1589745.2% 같은 극단 수치)은 타당하다. 기준값이 매우 작을 때 배수 표기를 병기하거나 상한을 두는 편이 읽기 좋다.
- Goal 의 "좋아요/다운로드 추세 수치"는 surge 글에만 구현됐다. 비-surge 글은 여전히 단일 시점 값만 있다. 이력이 1일뿐인 현 시점에서는 어떤 글도 추세를 낼 수 없으므로 즉시 결함은 아니지만, 보고서가 "5개 글 모두 충족"이라고 쓴 것은 과대 서술이다. 이력이 2일 이상 쌓이면 모든 글에 "N일 전 대비 좋아요 +a, 다운로드 +b" 문장을 넣도록 후속 작업이 필요하다.

## 4. 수정 지시

### 4-a. 구현(scripts/collect.py, 테스트 포함)
1. `find_previous_model` 은 후보를 **자기 글의 created_at 보다 먼저 등록된**(created_at 이 더 이른) 같은 org·task 모델로 제한하고, 그중 created_at 이 가장 늦은 것을 고른다. published_at 은 보조 키로만 쓴다. 조건에 맞는 모델이 없으면 None 을 돌려 "비교 대상 없음(최초 발행)" 문장을 쓴다. created_at 이 비어 있는 모델은 후보에서 제외한다.
2. 이 규칙을 고정하는 테스트 추가: 형제가 더 나중에 등록된 경우 None, 더 먼저 등록된 형제 여러 개 중 가장 최근 것 선택, created_at 없는 형제 제외.
3. `build_related_models` 의 "같은 org" 섹션에 task 필터를 추가하거나, README 23행을 실제 동작("같은 기관 최대 3개 + 같은 태스크 최대 3개")에 맞게 고쳐 둘 중 하나로 정합시킨다.
4. 기준값이 1,000 미만인 다운로드 변화율은 "%"와 함께 "약 N배" 를 병기한다(선택).
5. `--regenerate` 로 글을 다시 만들고 push.
